# Development Roadmap

> 路线图用于控制开发顺序。每个阶段完成验收后再进入下一阶段；实际技术任务应根据仓库中的实现和测试调整。

## Phase 0 — 项目定义与技术决策

目标：让 Codex 获得稳定的项目上下文。

- [x] 创建 GitHub 仓库。
- [x] 建立项目说明和 Codex 协作规范。
- [x] 整理学习者档案。
- [x] 整理 30 天课程目录。
- [x] 定义产品需求和学习设计。
- [ ] 确认技术栈。
- [ ] 确认数据持久化和备份方案。
- [ ] 确认部署与访问方式。
- [ ] 确认音频和学习素材来源。

验收：关键技术选择有明确结论，且未决定事项被记录。

## Phase 1 — 网站骨架与核心导航

目标：建立可以运行和浏览的基础网站。

- 项目初始化和开发命令。
- 页面布局、导航和响应式基础。
- 首页空状态。
- 课程目录与阶段展示。
- 基础组件和内容组织方式。
- 基础测试与构建流程。

验收：
- 项目可以按文档启动。
- 桌面和手机布局可用。
- 课程目录与课程文档一致。
- 没有用静态假数据伪装学习记录。

## Phase 2 — 课程学习 MVP

目标：让学习者真正完成一节课。

- 课程数据结构。
- 课程详情页。
- 学习目标、知识、例句和练习模块。
- 选择题/判断题/填空等基础题型。
- 答案与解析。
- 课程进度记录。

验收：
- 能完成一节完整课程。
- 刷新后课程状态符合已确认的存储方案。
- 练习反馈准确且可追溯。

## Phase 3 — 词汇、语法与复习

目标：建立知识点和错误记录之间的联系。

- 词汇列表和词条详情。
- 词汇主动回忆练习。
- 语法知识点页面。
- 错题记录。
- 按课程或知识点进入复习。
- 复习历史。

验收：
- 练习错误能关联具体知识点。
- 能再次练习并查看前后记录。
- 词汇和语法内容不依赖单个页面硬编码。

## Phase 4 — 学习记录与阶段测评

目标：形成学习闭环和阶段反馈。

- 学习历史。
- 课程和阶段进度。
- Day 7、15、23、30 测评框架。
- 测评结果和错题回顾。
- 基础薄弱点汇总。

验收：
- 统计数据来自实际记录。
- 不把活动量误报为能力水平。
- 开放性任务有明确评价标准。

## Phase 5 — 听力、阅读、口语与写作扩展

目标：提升综合语言训练能力。

- 接入经确认来源的音频。
- 听力任务和文本揭示。
- 分级阅读材料。
- 口语任务与自评。
- 写作任务和修改记录。
- 录音功能（若技术方案和隐私边界明确）。

验收：
- 无素材时有明确状态。
- 内容难度与课程目标相匹配。
- 练习和学习记录完整。

## Phase 6 — 个性化增强

在核心流程稳定后再考虑：
- 自动间隔复习。
- 学习计划建议。
- AI 对话和表达反馈。
- 更细致的错误分类。
- 数据导出、备份和跨设备同步。
- PWA 或其他离线能力。

验收：每项增强都有明确价值、隐私说明、成本评估和测试。

## 开发协作规则

- 一次只推进一个可验收的垂直功能。
- 每次改动说明涉及文件和用户可见变化。
- 不因路线图存在就提前实现后续阶段。
- 每阶段完成后更新本文件和 README。
